<a id="mean_hr"></a>
## 1. `mean_hr` — 平均心率

| | |
|---|---|
| **型別** | `number \| null` |
| **狀態** | ✅ 已在 `/vitals`（欄位名 `hrv.meanHr`） |
| **單位** | bpm |
| **實測值** | 68 ~ 78 |
| **30 秒可信度** | **高** |
| **null 條件** | 拍數 < 9（HRV 暖機門檻）、無手指、沉澱期 |

### 怎麼算

```
meanRr  = 視窗內所有 RR 的算術平均（ms）
mean_hr = 60000 / meanRr
```

實作：`Max30102HrvCalculator.hrvFrom()` 的 `meanHr` 欄位。

### ⚠️ 與 `/vitals` 的 `bpm` 不是同一個東西

| | 取樣範圍 | 統計量 | 特性 |
|---|---|---|---|
| `bpm` | 最近 **6 拍** | **中位數** | 反應快、抗離群，適合即時顯示 |
| `mean_hr` | 視窗內**全部**（約 35 拍） | **平均數** | 穩定，適合當這次量測的代表值 |

**推薦用 `mean_hr`。** `bpm` 是為了畫面上的即時數字設計的，會跟著最近
幾拍跳動；做推薦決策應該用整段的代表值。

兩者在穩定的量測下通常差 1~3 bpm（例如 `bpm` 73 / `mean_hr` 69）。

### 相關欄位

- [`sdnn`](#sdnn)、[`rmssd`](#rmssd) — 同一組 HRV 統計
- [`pns`](#pns)、[`stress`](#stress) — 內部會用到平均 RR / 平均心率

<a id="sdnn"></a>
## 2. `sdnn` — 整體變異

| | |
|---|---|
| **型別** | `number \| null` |
| **狀態** | ✅ 已在 `/vitals`（`hrv.sdnn`） |
| **單位** | ms |
| **實測值** | 30 ~ 48 |
| **30 秒可信度** | **中** — 可算，但有系統性偏差，見下 |
| **null 條件** | 同 `mean_hr` |

### 怎麼算

視窗內所有 RR 的**樣本標準差**（N−1 自由度）：

```
sdnn = √( Σ(rr − mean)² / (N − 1) )
```

### ⚠️ 30 秒的 SDNN 會系統性偏低

這是這個欄位最重要的注意事項。

SDNN 涵蓋**所有頻率**的變異，包含週期很長的慢成分（呼吸以外的血壓調節、
體溫調節等，週期 25 秒到數分鐘）。30 秒的窗根本裝不下那些慢週期，
所以它們對變異的貢獻整段被截掉。

結果：**同一個人、同一個當下，30 秒量出來的 SDNN 一定比 5 分鐘量出來的小。**

這**不是雜訊，是偏差**（bias），不會因為多量幾次而平均掉。

**實務上的意思**：

- ✅ 同一台裝置、同樣 30 秒窗，前後比較 → 有意義
- ❌ 拿我們的 SDNN 跟攝影機端的比 → 除非兩邊窗長相同，否則不可比
- ❌ 拿去對照文獻上的常模值（那些幾乎都是 5 分鐘量的）→ 會系統性偏低

### 相關欄位

- [`rmssd`](#rmssd) — 不受這個問題影響，30 秒下更可靠
- 附錄 B 的 LF/HF 實測 — 同一個窗長效應的極端版本

<a id="rmssd"></a>
## 3. `rmssd` — 逐拍變異 ★ 最可信

| | |
|---|---|
| **型別** | `number \| null` |
| **狀態** | ✅ 已在 `/vitals`（`hrv.rmssd`） |
| **單位** | ms |
| **實測值** | 28 ~ 43 |
| **參考常模** | 健康成年人約 42 ± 15 ms |
| **30 秒可信度** | **高** ★ |
| **null 條件** | 同 `mean_hr` |

### 怎麼算

相鄰兩拍 RR 差值的均方根：

```
rmssd = √( Σ(rr[i] − rr[i−1])² / pairs )
```

⚠️ **只累加「時間相鄰」的配對。** 如果中間有拍被過濾器剔掉（漏拍、
誤拍、SQI 差），那個跨洞的相減會被跳過，分母只算真正連續的對數。
不這樣做的話 RMSSD 會被灌水。

實作在 `Max30102HrvCalculator.hrvFrom()`，靠比對 `startAbs` / `endAbs`
判斷連續性。

### 為什麼這是我們最推薦的指標

**① 機制清楚 —— 它是純副交感的**

逐拍的快速變化只有迷走神經跟得上：

| | 傳導物質 | 作用時間 |
|---|---|---|
| 迷走神經（副交感） | 乙醯膽鹼 | **一拍之內**（分解極快） |
| 交感神經 | 正腎上腺素 | **數秒**（清除慢） |

交感神經在生理上就是一個低通濾波器，**物理上產生不出這麼快的變化**。
所以逐拍變異只可能來自副交感。這不是統計觀察，是機制上的必然。

**② 短窗有效**

文獻上 10~30 秒的 RMSSD 與 5 分鐘的一致性經過驗證，是超短時 HRV
（ultra-short-term HRV）裡最站得住的一個。這跟 [`sdnn`](#sdnn) 和
[`lf_hf`](#lf_hf) 形成明顯對比。

**③ 等同於 HF，但不需要頻譜分析**

RMSSD 是一階差分，在訊號處理上就是**高通濾波器**，本質上就在量高頻成分。
它與頻域的 HF 相關性通常 **> 0.9**。

| | 需要什麼 | 30 秒可用 |
|---|---|---|
| HF | 頻譜分析，至少 60 秒 | 邊緣 |
| **RMSSD** | 只要相鄰兩拍相減 | ✅ 已驗證 |

> **如果你需要「這個人放鬆還是緊繃」的訊號，用這個。**
> 它提供了 [`lf_hf`](#lf_hf) 原本想表達的、而且唯一機制站得住的那一半。

### 相關欄位

- [`ln_rmssd`](#ln_rmssd) — 取對數後的版本，適合線性運算
- [`pns`](#pns) — 內部以 RMSSD 為主要成分
- `hrv.sd1` — 恆等於 `rmssd / √2`，同一份資訊

<a id="ln_rmssd"></a>
## 4. `ln_rmssd` — RMSSD 的自然對數

| | |
|---|---|
| **型別** | `number \| null` |
| **狀態** | 🟡 已算出，未導出 |
| **單位** | 無（對數值） |
| **實測值** | 3.36 ~ 3.75 |
| **30 秒可信度** | **高**（同 `rmssd`） |
| **null 條件** | `rmssd` 為 null 或 ≤ 0 |

### 怎麼算

```
ln_rmssd = Math.log(rmssd)     // 自然對數，不是 log10
```

### 為什麼要取對數

RMSSD 的族群分布接近**對數常態**（右偏：多數人集中在低值，少數人拖出
長尾）。直接對原始值做平均、比較、線性迴歸都會被長尾拉偏。

取 ln 之後分布接近常態，才適合：

- 計算平均與標準差
- 做線性運算或迴歸
- 畫在等距的刻度上

換算直覺：

| `rmssd` | `ln_rmssd` |
|---|---|
| 20 ms | 3.00 |
| 30 ms | 3.40 |
| 42 ms（常模） | 3.74 |
| 60 ms | 4.09 |

### 💡 你那邊一行就能自己算

```js
const ln_rmssd = v.rmssd != null && v.rmssd > 0 ? Math.log(v.rmssd) : null;
```

不必等我們導出。`rmssd` 已經在 `/vitals` 裡了。

### 相關欄位

- `hrv.hrvScore` — 我們另有一個 `ln(rmssd) × 20` 的親切分數（上限 150），
  見[附錄 C](#appendix-c)

<a id="lf_hf"></a>
## 5. `lf_hf` — 低頻/高頻比 🔴 恆為 null

| | |
|---|---|
| **型別** | `number \| null` |
| **狀態** | 🔴 **恆為 null（刻意，不是還沒做）** |
| **原本應該是什麼** | LF 功率 ÷ HF 功率 |
| **我們算得出來嗎** | **算得出來**，但不可信 |
| **實測（僅供理解，不對外送）** | 0.54 ~ 2.48 |

### 一句話

**LF/HF 在我們的量測情境下不收斂** —— 它在單次 5 分鐘的錄製裡就從
−39% 漂到 +63%。給一個數字會比給 null 更糟，因為那個數字看起來完全
合理，而下游沒有任何方法判斷它不可信。

### LF 與 HF 分別在量什麼

HRV 頻譜分析是把 **RR 間期序列的起伏**拆解成不同週期的成分：

| 頻帶 | 範圍 | 週期 | 生理來源 |
|---|---|---|---|
| **HF** | 0.15~0.4 Hz | 2.5~6.7 秒 | 呼吸性竇性心律不整（RSA） |
| **LF** | 0.04~0.15 Hz | 6.7~25 秒 | 壓力反射振盪（Mayer wave） |

**HF 的機制很清楚。** 吸氣時腦幹抑制迷走神經輸出 → 心跳加速；吐氣時
解除 → 心跳減慢。正常呼吸 12~20 次/分 = 0.2~0.33 Hz，**HF 頻帶的邊界
就是照人類呼吸速率畫的**。而且如 [`rmssd`](#rmssd) 所述，交感神經物理上
產生不出這麼快的振盪，所以 HF 只可能是副交感的。

**LF 混濁得多。** 主峰 0.1 Hz 來自壓力反射的負回饋迴路：血壓上升 →
壓力感受器 → 腦幹 → 心跳變慢、血管舒張 → 血壓下降 → 反覆。帶延遲的
負回饋必然振盪，延遲長度決定它落在 0.1 Hz。

但那個迴路**兩條神經都用**：對心臟走迷走（快），對血管走交感（慢）。
所以 LF 裡兩種成分混在一起。它還會被污染：

- **慢呼吸** —— 一分鐘 6 次 = 0.1 Hz，呼吸節奏直接搬進 LF 帶
- 姿勢、體溫調節、腎素系統的慢成分往上滲
- VLF（更慢的成分）洩漏 —— 我們實測看到的就是這個

`LF/HF` 被解釋為「交感/副交感平衡」是 Pagani 1986 提出的，但那個前提
已被推翻 —— 例如阻斷**迷走**神經的阿托品會大幅消掉 LF，若 LF 是純交感
就不該如此。

### 為什麼我們不給

三個實測結論（完整資料見[附錄 B](#appendix-b)）：

1. **30 秒不可用** —— 對 5 分鐘標準偏 **42%**，只有 6/28 落在 ±20% 內
2. **2 分鐘也不是可靠基準** —— 偏 **26%**，1/7 落在 ±20% 內
3. **拉長量測時間不會解決** —— 訊號本身在漂移，不是取樣不足

所以這不是「我們的裝置做不到」，而是**這個量在這個情境下量不到穩定的
東西**。就算讓使用者坐 5 分鐘，拿到的也只是漂移曲線上的一個點。

> Apple 健康 App 的 HRV 只提供 SDNN，同樣不提供 LF/HF。
> 這不構成證據，但可以視為獨立達成的相同判斷。

### 該用什麼取代

**LF/HF 裡機制真正站得住的那一半是 HF（副交感），而 [`rmssd`](#rmssd)
與 HF 的相關性 > 0.9，且 30 秒驗證過、已經在回應裡了。**

給不了的是交感那一半 —— 而那一半 LF 本來就沒有真的量到。

### 實作上的保證

`toStrapiJson()` 的 `lf_hf` 永遠是 null，且有測試釘著
（`test/k2_vitals_metrics_test.dart` 的「誠實性規則」那一組），
避免日後被誰「順手修好」。

核心裡的 `HrvSpectrum.lfUsable` 會在窗長不足時回 false（門檻 110 秒），
`VitalsMetrics.lfHf` 看到 false 就回 null。30 秒窗永遠落在這一類。

<a id="sqi"></a>
## 6. `sqi` — 訊號品質閘門

| | |
|---|---|
| **型別** | `number \| null`（我們給 `1` 或 `0`） |
| **狀態** | 🟡 已算出，未導出（布林版 `sqiOk` **已在 `/vitals`**） |
| **實測值** | 良好貼合時穩定為 `1` |
| **更新頻率** | 每個演算窗一次（5 秒） |

### 這是二元閘門，不是分數

你的介面型別是 `number`，但我們的 SQI 本質上是**通過/不通過**，
所以映射成 `1` / `0`。

它回答的是：「這一輪偵測到的心跳可不可信？」不通過的那一輪，該輪的
拍**不會進入 RR 序列**，所以 HRV 數值會維持前值不動。

### 三個條件全過才是 1

| 零件 | 量什麼 | 門檻 |
|---|---|---|
| `cv` | 拍間距的變異係數 —— **節律規不規律**（時間軸） | < 0.35 |
| `spike` | 最大起伏 ÷ 典型起伏 —— **有沒有體動**（振幅軸） | < 5.0 |
| `keptCount` | 過完粗篩還剩幾個可用間距 | ≥ 2 |

**`cv`**：先把間距過兩道粗篩（生理閘門 30~240 bpm、與中位數比
±50% 剔除），剩下的算標準差 ÷ 平均。

**`spike`**：分子是 5 秒窗內去趨勢訊號的**最大正向起伏**，分母是同一段
所有正值的**第 70 百分位**（代表「典型的大起伏」）。比值在問：
「最猛的那一下是平常的幾倍？」正常脈搏約 1~2，體動時飆高。

⚠️ 分母不是只取峰值點，是取全部正值樣本 —— 所以它對「兩拍之間突然
晃一下」也有反應，那個位置根本不是峰。

**兩個維度互補**：體動可能只毀振幅不毀節律，也可能反過來。一個被遮住
還有另一個接得住。

### ⚠️ 目前給不出連續值

三個零件裡**只有 `spike` 被核心導出**（欄位名 `spikeMax`），
`cv` 與 `keptCount` 只活在 `Max30102Sqi` 物件內部，只有 `ok` 逃得出來。

要提供 0~1 的連續品質分數，需要：

1. 改交接核心，把 `cv` 一起導出
2. 決定 `cv` 與 `spike` 怎麼加權合成一個數 —— **這一步沒有依據**，
   兩個門檻本身都還是觀測初值。硬做等於憑空定義一個數字。

**如果你需要連續值，告訴我用途**，我再判斷該給 `spike` 原始值、
還是真的做一個合成分數（並說明它沒校準過）。

### 相關欄位

- [`confidence`](#confidence) — 把 `sqi` 與拍數合起來的三級評等，
  多數情況下比裸的 `sqi` 好用
- `spikeMax`（[附錄 C](#appendix-c)）— 連續的體動指標

## 7. `snr_db` — 波形訊噪比

| | |
|---|---|
| **型別** | `number \| null` |
| **狀態** | 🟡 已算出，未導出 |
| **單位** | dB |
| **實測值** | 3.3 ~ 10.1 |
| **null 條件** | 波形不足 5 秒、或沒有 `bpm`（定位不到基頻） |

### ⚠️ 這不是 SQI，兩者不能互相換算

| | 量什麼 | 域 |
|---|---|---|
| `sqi` / `spike` | 振幅離群比 | **時域** |
| `snr_db` | 脈搏諧波能量 ÷ 其餘頻帶能量 | **頻域** |

做這一支純粹是因為你的介面有這個欄位，而攝影機端給的就是頻域 SNR。

### 怎麼算

rPPG 領域的常見定義：

1. 取原始 IR 波形，去趨勢（減平均）+ 加 Hann 窗（降低頻譜洩漏）
2. 補零到 2 的冪次 → radix-2 FFT
3. **訊號** = 基頻 f₀（= `bpm` / 60）±0.1 Hz 與二次諧波 2f₀ ±0.2 Hz 的能量
4. **雜訊** = 0.5 ~ 5 Hz 內其餘的能量
5. `snr_db = 10 × log₁₀(訊號 / 雜訊)`

### 怎麼讀

數字越高代表脈搏波形越乾淨（能量集中在心跳的基頻與諧波上）。

實測 3.3 ~ 10.1 dB，都是在 `sqi = 1`、`confidence = good` 的情況下量的
—— 所以**這個範圍內的變化不代表量測失敗**，只反映貼合鬆緊與灌流狀況。

⚠️ 目前**還沒建立「多少 dB 以下該拒絕」的門檻**。要定門檻需要收一批
含明顯失敗案例的資料。現階段建議當參考值，把關交給
[`sqi`](#sqi) 與 [`confidence`](#confidence)。

## 8. `confidence` — 量測可信度

| | |
|---|---|
| **型別** | `'good' \| 'rough' \| 'very rough' \| null` |
| **狀態** | 🟡 已算出，未導出（三個依據都已在 `/vitals`） |
| **實測值** | 正常貼合時為 `'good'` |

### 這不是生理指標，是工程指標

它回答的是「這次量測的數字該信幾分」，跟受測者的身體狀況無關。

### 判定規則

| 條件（由上而下先符合先回） | 回傳 |
|---|---|
| `settling` 為 true（手指剛放上） | `null` |
| 拍數 < 9 | `null` |
| 拍數 ≥ 25 **且** `sqiOk` | `'good'` |
| 拍數 ≥ 15 | `'rough'` |
| 其餘（拍數 9 ~ 14） | `'very rough'` |

### 三個依據

**① 拍數（`hrv.beats`）** —— HRV 統計量的抽樣誤差隨拍數縮小。
核心的 HRV 暖機門檻是 **9 拍**（不足直接不出 HRV）。30 秒在 70 bpm
約收 35 拍，所以正常量測會落在 `'good'`。

**② `sqiOk`** —— 這一輪訊號品質是否過關。**攝影機端沒有對等的東西**，
這是接觸式感測器的優勢：我們知道手指有沒有貼好。

**③ `settling`** —— 手指剛放上、訊號還沒穩定，這時的數字不該用。

### 💡 你那邊也可以自己算

三個依據都已經在 `/vitals` 裡（`hrv.beats`、`sqiOk`、`settling`），
所以不等我們導出也能自己組。要調整門檻也容易。

### 建議的處理

```js
if (v.settling) return;                 // 還沒穩，不要用
if (v.confidence === null) return;      // 拍數不足
if (v.confidence === 'very rough') {
  // 可以用，但建議標示或請使用者重量
}
```

<a id="pns"></a>
## 9. `pns` — 副交感神經活性指數

| | |
|---|---|
| **型別** | `number \| null` |
| **狀態** | 🟡 已算出，未導出 |
| **單位** | 無（z-score 平均） |
| **典型範圍** | −3 ~ +3，0 = 常模平均 |
| **實測值** | −1.15 ~ −0.16 |
| **30 秒可信度** | **中** |

### 怎麼算

三個成分各自對常模做 z-score 再平均：

```
pns = ( z(meanRr) + z(rmssd) + z(sd1) ) / 3
z(x) = (x − 常模均值) / 常模標準差
```

| 成分 | 常模均值 ± 標準差 | 意義 |
|---|---|---|
| 平均 RR | 926 ± 90 ms | 心跳越慢 → 迷走張力越高 |
| RMSSD | 42 ± 15 ms | 逐拍變異，迷走調控 |
| SD1 | 29.7 ± 11 ms | Poincaré 短軸 |

越大代表越偏「休息與消化」（放鬆、恢復）。

### ⚠️ 兩個必須知道的限制

**① 常模不是 Kubios 的**

Kubios 的 PNS index 是拿他們自己的資料庫做 z-score。我們沒有那份資料，
用的是文獻上健康成年人的參考值。

**方向可信，絕對值不會跟 Kubios 對齊。** 要對齊只有兩條路：拿到那份
常模，或自己收一批人建立基準。

**實務上的意思**：同一台裝置前後比較有意義；拿去跟 Kubios 或其他
裝置的 PNS 數字比對沒有意義。

**② SD1 = RMSSD / √2 是恆等式**

這是數學上的恆等關係（我們的程式碼就是這樣算的）。所以那三個成分
其實**只有兩份獨立資訊**，SD1 那一項等於把 RMSSD 加權兩次。

這是 Kubios 自己的定義，照做即可，但別誤以為它是三個獨立證據。

### 相關欄位

- [`rmssd`](#rmssd) — 主要成分，本身就是很好的副交感指標
- [`ans`](#ans) — 時域版的自律平衡由 `pns` 與交感指數相減得到

## 10. `ans` — 自律神經平衡 🔴 恆為 null

| | |
|---|---|
| **型別** | `number \| null` |
| **狀態** | 🔴 **恆為 null（刻意）** |
| **我們有替代值嗎** | **有**，但定義不同，見下 |

### 兩個獨立的理由

**① 你的 `ans` 源自 LF/HF，而 [`lf_hf`](#lf_hf) 我們不給。**

**② 就算給了也是另一個東西。**

我們算得出一個**時域的替代值**：

```
ansTimeDomain = SNS − PNS
```

| 指數 | 成分 | 全時域？ |
|---|---|---|
| PNS | 平均 RR、RMSSD、SD1 | ✅ |
| SNS | 平均心率、`stress`（√SI）、SD2（取負號） | ✅ |

正值偏交感（緊張），負值偏副交感（放鬆）。**實測值 1.14 ~ 2.97。**

它的價值在於：**30 秒就算得出來，而 LF/HF 不行。**

但它與 LF/HF 導出的 `ans` **定義不同、尺度不同**，兩台裝置的數字
**不可互相比較，也不該存進同一個欄位**。

### 如果你希望我們填這個欄位

可以，但要先講定三件事：

1. 填進去的是**時域替代值**，不是 LF/HF 導出的自律平衡
2. 語意與攝影機端的 `ans` 不同 —— 任何跨裝置的比較或彙總邏輯會出錯
3. LLM prompt 裡若對 `ans` 有既定的解讀基準，那個基準對這個值不適用

**未經你確認我們不會自己塞。** 偷換定義比留 null 更難除錯。

### 相關欄位

- [`pns`](#pns) — 副交感側，可以單獨使用
- [`stress`](#stress) — 交感側的粗略參考
- [`rmssd`](#rmssd) — 若只需要「放鬆程度」，這個最可靠

<a id="stress"></a>
## 11. `stress` — Baevsky 壓力指數

| | |
|---|---|
| **型別** | `number \| null` |
| **狀態** | 🟡 已算出，未導出 |
| **單位** | 無（√SI） |
| **實測值** | 10.9 ~ 16.8 |
| **30 秒可信度** | **低** —— 見下 |
| **null 條件** | 拍數 < 5、或所有 RR 完全相同（全距為 0） |

### 這是什麼

俄國生理學家 Baevsky 提出的指標，最早用於蘇聯太空醫學評估生理負荷。
Kubios 沿用並取平方根後稱為 "Stress index"。

**純時域**（不需要頻譜分析），所以它是 30 秒窗下少數還算得出來的
**交感側**指標。

### 怎麼算

把視窗內的 RR 做成直方圖（50 ms 一格），取三個量：

| 符號 | 中文 | 定義 |
|---|---|---|
| **Mo** | 眾數 | 最多拍落在哪一格（該格中心，秒） |
| **AMo** | 眾數振幅 | 那一格佔全體的百分比 |
| **MxDMn** | 變異全距 | 最大 RR − 最小 RR（秒） |

```
SI     = AMo / (2 × Mo × MxDMn)
stress = √SI        ← 回傳這個（取平方根讓分布接近常態）
```

**直覺**：心跳被交感壓得又快又規律 → 直方圖又高又窄 → AMo 大、
MxDMn 小 → SI 衝高。放鬆時心跳散得開，SI 低。

**參考**：Baevsky SI 靜息常態約 50~150，對應 √SI 約 7~12。
我們實測 10.9 ~ 16.8（換算 SI 約 119~282），偏高側。

### ⚠️ 30 秒下這個數字很薄

不只是「樣本少所以有雜訊」—— **SI 剛好由兩個對小樣本最敏感的統計量
組成**：

- **`AMo`** 是「最高那格佔多少百分比」。35 個樣本分到 8~10 格，每格
  3~5 個，**哪一格最高幾乎是隨機的**。
- **`MxDMn`** 是**全距**（max − min），統計上小樣本行為最差的一種量
  —— 只由兩個極端值決定，多收一拍就可能整個改變。

**建議當粗略的方向性訊號使用，不要當精確數值。**

實測上它在連續幾次量測之間還算穩定（16.6 → 16.8），但那是同一段時間內；
跨時段的穩定性尚未驗證。

## 附錄 A：資料是怎麼來的

```
MAX30102 感測器
   │  紅光 + 紅外光，100 Hz
   ▼
原始波形 (RED / IR)
   │  截尾平滑 → 去趨勢 → prominence 找波谷
   ▼
波谷的絕對時刻
   │  生理閘門 (30~240 bpm)
   │  誤拍過濾 (與近 9 拍中位數差 > 40% 剔除)
   │  SQI 閘門 (整輪不過 → 該輪的拍不記)
   ▼
RR 間期序列  ←──── 所有 HRV 指標的唯一來源
   │
   ├─→ 時域統計 ──→ sdnn, rmssd, pnn50, sd1, sd2, mean_hr
   ├─→ 直方圖   ──→ stress (Baevsky SI)
   ├─→ 常模 z-score ─→ pns, sns → ansTimeDomain
   └─→ 頻域 (Lomb-Scargle) ─→ LF, HF → lf_hf  ← 不對外送
```

**關鍵觀念：感測器只負責「報時」。**

光訊號唯一的工作是判斷每一拍發生在哪個時刻。一旦有了那串時間戳，
後面所有指標都是對那串數字做算術，跟光本身無關。

因此指標的可信度取決於兩件事：

1. **拍的時刻抓得準不準** → 由 [`sqi`](#sqi) / [`confidence`](#confidence) 反映
2. **那個指標需要多長的觀測窗** → 這就是 [`lf_hf`](#lf_hf) 失效的原因

### 為什麼 RR 頻譜用 Lomb-Scargle 而不是 FFT

FFT 有兩個前提，RR 序列**兩個都不成立**：

- **等間隔取樣** —— RR 的時間戳由心跳決定，本來就不等間隔
- **沒有缺漏** —— SQI 差與誤拍過濾會在序列上留下洞

Lomb-Scargle 是為不等間隔資料設計的：它對每個頻率直接做最小平方擬合，
不需要重取樣或內插。

<a id="appendix-b"></a>
## 附錄 B：LF/HF 實測完整資料

### 方法

錄製一段連續資料，把**同一段**切成不同長度的滑動窗，各自算 LF/HF。
這樣唯一的變數就是窗長 —— 受測者、心跳、生理狀態全部相同。

**不是量兩次比較** —— 兩次之間人的呼吸與狀態都變了，測到的差異會分不清
是窗長造成的還是生理變化造成的。

### 「偏差 %」是誰跟誰比

**基準 = 用完整錄製長度算出來的那一個 LF/HF。**
那次 5 分鐘錄製的基準是 **0.91**（298 秒、344 拍、LF 873 ms²、HF 959 ms²）。

```
偏差% = (這個窗算出來的值 − 基準) ÷ 基準 × 100
```

實際代入（2 分鐘窗那一組，基準 0.91）：

| 窗 | 這段算出來 | 計算 | 偏差 |
|---|---|---|---|
| 0–120s | 0.70 | (0.70 − 0.91) ÷ 0.91 | −23% |
| 30–150s | 0.55 | (0.55 − 0.91) ÷ 0.91 | **−39%** |
| 60–180s | 0.67 | (0.67 − 0.91) ÷ 0.91 | −26% |
| 90–210s | 0.59 | (0.59 − 0.91) ÷ 0.91 | −35% |
| 120–240s | 0.86 | (0.86 − 0.91) ÷ 0.91 | −5% |
| 150–270s | 1.15 | (1.15 − 0.91) ÷ 0.91 | +26% |
| 180–300s | 1.48 | (1.48 − 0.91) ÷ 0.91 | **+63%** |

所以「−39%」的意思是：**只看第 30~150 秒這兩分鐘，算出來的 LF/HF 是
0.55，比用完整 5 分鐘算出來的 0.91 低了 39%。**

**「偏差中位數」**是把上面七個數字取絕對值（不管正負、只看差多少）
排序後取中間那個：

```
5, 23, 26, [26], 35, 39, 63   →  中位數 = 26%
```

用中位數而非平均：實測遇過手抖那次有單一窗偏差 818%，平均會被它整個
帶走，中位數不會。

### 結果一：對 5 分鐘基準

| 窗長 | 偏差中位數 | 落在 ±20% 內 |
|---|---|---|
| **30 秒**（我們產品的長度） | **42%** | 6 / 28 |
| **2 分鐘** | **26%** | 1 / 7 |

30 秒的結果在預期內。**2 分鐘那一列才是關鍵**：連 2 分鐘的窗都偏離
5 分鐘參考達 26%。所以問題不只是「30 秒太短」——**2 分鐘也不是穩定的
參考基準**。

### 結果二：它在漂移，不是在抖動

把 2 分鐘窗照時間排開（見上表）：

```
−23% → −39% → −26% → −35% → −5% → +26% → +63%
```

**單調往上爬**，在單一段 5 分鐘錄製之內。

這代表 LF/HF **不是繞著某個穩定值上下抖、而我們取樣太短**
—— **它本身就一直在漂移**。任何窗長都逃不掉；窗只決定你在漂移曲線的
哪一段取樣。

也就是說 **5 分鐘基準本身可能也不是「真值」**，只是漂移曲線上的一個
平均。我們沒有 10 分鐘的參考可以驗證它。

### 結果三：跨次錄製的基準也不穩

半小時內對同一個人做五次獨立的 2 分鐘錄製：

| # | 基準 LF/HF | 30 秒窗偏差中位數 | ±20% 內 | 拍數 |
|---|---|---|---|---|
| 1 | 0.60 | 48% | 3/10 | 140 |
| 2 | 0.84 | 58% | 2/10 | 138 |
| 3 | 0.20 | 50% | 2/10 | 129 |
| 4 | 0.21 | 58% | 2/10 | 123 |
| 5 | 0.60 | 64% | 2/10 | 143 |

加上更早的兩次（1.06、1.97），**基準從 0.20 跳到 1.97，差了將近 10 倍**。

> 換個方式想：如果量身高量五分鐘得到 170 公分，只取其中兩分鐘卻算出
> 130 公分、換另外兩分鐘算出 277 公分 —— 身高當然不會這樣，但 LF/HF
> 就是這樣。

### 工具

實驗工具在桌面 App 的 K2 頁面（「LF 窗長對照實驗」區塊），
可選 2 分鐘或 5 分鐘錄製，自動切窗、算偏差、累積歷次結果。
實作：`lib/main_mode/max30102_K2/ui/k2_lf_experiment.dart`

⚠️ **上限原本是 100，已放寬到 150。** 100 分對應 RMSSD 148 ms，而深慢
呼吸下的高變異真的量得到 130~230 ms（實測過），會直接卡在滿分、分不出
「很好」與「極高」。150 對應 RMSSD ≈ 1808 ms，實務上等於不再設限。

**所以分數可能大於 100** —— 呈現層若有進度條或百分比視覺，要自己處理溢出。

### 建議額外導出

核心已經算好、只是還沒放進 HTTP 回應：

**★ `rrPoints`（RR 間期陣列）—— 投報率最高**

所有 HRV 指標都是從這一條序列導出的。有了它，你可以自己算任何需要的
東西（pNN20、其他壓力指數、自訂分數），**不用一個一個等我們加欄位**。

**`spikeMax`** —— 連續的體動指標，可能對應你的 [`activity`](#activity)。

**`cv`** —— [`sqi`](#sqi) 的另一個零件；若要連續版的品質分數會需要它
（需改交接核心）。
