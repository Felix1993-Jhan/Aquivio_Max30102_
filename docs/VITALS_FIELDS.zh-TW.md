`aquivio-station/src/hooks/useVitalScans.ts` 的 `VitalsResult` 與

<a id="pipeline"></a>
## 2. 資料是怎麼來的

```
MAX30102 感測器
   │  紅光 + 紅外光，100 Hz
   ▼
原始波形 (RED / IR)
   │  截尾平滑 → 去趨勢 → 找波谷
   ▼
波谷的絕對時刻
   │  生理閘門 (30~240 bpm) → 誤拍過濾 (>40% 剔除) → SQI 閘門
   ▼
RR 間期序列  ←──── 所有 HRV 指標的唯一來源
   │
   ├─→ 時域：SDNN, RMSSD, pNN50, SD1, SD2
   ├─→ 直方圖：Baevsky 壓力指數
   ├─→ 常模 z-score：PNS
   └─→ 頻域（Lomb-Scargle）：LF, HF  ← §4 說明為什麼不給
```

**關鍵觀念：感測器只負責「報時」。**

光訊號唯一的工作是判斷每一拍發生在哪個時刻。一旦有了那串時間戳，
後面所有指標都是對那串數字做算術，跟光本身無關。

因此指標的可信度取決於**兩件事**：

1. 拍的時刻抓得準不準（訊號品質 → 由 `sqi` / `confidence` 反映）
2. 那個指標需要多長的觀測窗（→ 這就是 `lf_hf` 失效的原因）

<a id="fields"></a>
## 3. 欄位逐項說明

<a id="direct"></a>
### 3.1 直接提供（已在 `/vitals`）

#### `mean_hr` — 平均心率（bpm）

視窗內所有 RR 的平均值換算：`60000 / meanRr`。

⚠️ 與 `/vitals` 的 `bpm` **不同**：

| | 取樣範圍 | 統計量 |
|---|---|---|
| `bpm` | 最近 **6 拍** | **中位數** |
| `mean_hr` | 視窗內**全部**（約 35 拍） | **平均數** |

`bpm` 反應快、抗離群，適合即時顯示；`mean_hr` 穩定，適合做為這次量測的
代表值。**推薦用 `mean_hr`**。

#### `sdnn` — 整體變異（ms）

視窗內所有 RR 的標準差（N−1 自由度）。

⚠️ **30 秒的 SDNN 會系統性偏低。** SDNN 涵蓋所有頻率的變異，包含週期
很長的慢成分；30 秒的窗抓不到那些慢成分，所以數字會比 5 分鐘量出來的小。
這不是雜訊，是**偏差**——不同窗長的 SDNN 不能直接互相比較。

#### `rmssd` — 逐拍變異（ms）★ 最可信的指標

相鄰兩拍 RR 差值的均方根。

**這是我們最推薦的指標**，理由有三：

1. **機制清楚** — 逐拍的快速變化只有迷走神經（副交感）跟得上。交感神經
   的傳導物質作用要數秒，物理上產生不出這麼快的變化。所以 RMSSD
   是相當純粹的副交感指標。
2. **短窗有效** — 文獻上 10~30 秒的 RMSSD 與 5 分鐘的一致性經過驗證，
   是超短時 HRV 裡最站得住的一個。
3. **等同 HF** — RMSSD 是一階差分 = 高通濾波器，本質上就在量高頻成分。
   它與頻域的 HF 相關性通常 **> 0.9**，但不需要頻譜分析。

> **如果你需要「這個人放鬆還是緊繃」的訊號，用這個。**
> 它提供了 `lf_hf` 原本想表達的、而且是唯一機制站得住的那一半。

<a id="derived"></a>
### 3.2 衍生計算（已算出，未導出）

#### `ln_rmssd`

`Math.log(rmssd)`（自然對數）。

RMSSD 的分布接近對數常態，取 ln 之後才適合做線性運算、比較與繪圖。
可信度與 `rmssd` 相同。

**Koa 端一行就能自己算**，不一定要等我們導出。

#### `confidence` — `'good' | 'rough' | 'very rough' | null`

這**不是生理指標，是工程指標**：這次量測的數字該信幾分。

| 條件 | 回傳 |
|---|---|
| 沉澱期（手指剛放上） | `null` |
| 拍數 < 9 | `null` |
| 拍數 ≥ 25 **且** SQI 通過 | `'good'` |
| 拍數 ≥ 15 | `'rough'` |
| 其餘（拍數 ≥ 9） | `'very rough'` |

三個依據：

- **拍數** — HRV 統計量的抽樣誤差隨拍數縮小。核心的 HRV 暖機門檻是 9 拍
  （不足直接不出 HRV）。30 秒在 70 bpm 約收 35 拍。
- **SQI** — 這一輪訊號品質是否過關（見 §3.2 的 `sqi`）
- **沉澱期** — 手指剛放上、訊號還沒穩，這時的數字不該用

#### `pns` — 副交感神經活性指數

三個成分各自對常模做 z-score 再平均：

| 成分 | 常模均值 ± 標準差 |
|---|---|
| 平均 RR | 926 ± 90 ms |
| RMSSD | 42 ± 15 ms |
| SD1 | 29.7 ± 11 ms |

輸出約落在 −3 ~ +3，0 代表常模平均。越大代表越偏休息與恢復。

⚠️ **兩個必須知道的限制**

1. **常模不是 Kubios 的。** Kubios 的 PNS index 是拿他們自己的資料庫做
   z-score，我們沒有那份資料，用的是文獻上健康成年人的參考值。
   **方向可信，絕對值不會跟 Kubios 對齊。** 要對齊只能拿到那份常模，
   或自己收一批人建立基準。
2. **SD1 = RMSSD / √2 是恆等式。** 所以那三個成分其實只有兩份獨立資訊，
   SD1 那一項等於把 RMSSD 加權兩次。這是 Kubios 自己的定義，照做即可，
   但別誤以為它是三個獨立證據。

#### `stress` — Baevsky 壓力指數

**純時域**（不需要頻譜），所以是 30 秒窗下少數還算得出來的交感側指標。

把 RR 做成直方圖（50 ms 一格）取三個量：

| 符號 | 定義 |
|---|---|
| **Mo** | 眾數 — 最多拍落在哪一格（秒） |
| **AMo** | 眾數振幅 — 那一格佔全體的百分比 |
| **MxDMn** | 變異全距 — 最大 RR − 最小 RR（秒） |

```
SI = AMo / (2 × Mo × MxDMn)
```

回傳 Kubios 慣例的 **√SI**（取平方根讓分布接近常態）。

直覺：心跳被壓得又快又規律 → 直方圖又高又窄 → AMo 大、MxDMn 小 → SI 衝高。

⚠️ **30 秒下這個數字很薄。** 不只是「樣本少所以有雜訊」——SI 剛好由
**兩個對小樣本最敏感的統計量**組成：

- `AMo` 是「最高那格佔多少」。35 個樣本分到 8~10 格，每格 3~5 個，
  哪一格最高幾乎是隨機的。
- `MxDMn` 是**全距**，統計上小樣本行為最差的一種量——只由兩個極端值
  決定，多收一拍就可能整個改變。

**建議把它當粗略的方向性訊號，不要當精確數值使用。**

#### `snr_db` — 波形訊噪比（dB）

⚠️ 這**不是** SQI，兩者不能互相換算。SQI 是時域的振幅離群比，這裡是
頻域的能量比。

作法（rPPG 領域的常見定義）：

1. 去趨勢 + Hann 窗 → FFT
2. **訊號** = 基頻 f₀（= bpm/60）±0.1 Hz 與二次諧波 2f₀ ±0.2 Hz 的能量
3. **雜訊** = 0.5~5 Hz 內其餘的能量
4. `10 × log₁₀(訊號 / 雜訊)`

實測值大致落在 3~13 dB。數字越高代表脈搏波形越乾淨。

#### `sqi` — 訊號品質閘門（`1` / `0`）

你的介面型別是 `number`，我們的是**二元閘門**，所以映射成 1 / 0。

它每個演算窗（5 秒）算一次，三個條件全過才是 1：

| 零件 | 量什麼 | 門檻 |
|---|---|---|
| `cv` | 拍間距的變異係數（節律規不規律） | < 0.35 |
| `spike` | 最大起伏 ÷ 典型起伏（有沒有體動） | < 5.0 |
| `keptCount` | 過完粗篩還剩幾個可用間距 | ≥ 2 |

`cv` 管時間軸、`spike` 管振幅軸——體動可能只毀其中一個，兩個維度分開
看才蓋得住。

⚠️ **給不出連續值。** 三個零件裡只有 `spike` 被核心導出，`cv` 與
`keptCount` 只活在內部。要提供 0~1 的連續品質分數，得先改交接核心。
如果你需要，告訴我，那是可以做的。

### 3.3 恆為 null（刻意，不是還沒做）

#### `lf_hf`

**永遠回 `null`。** 完整理由與實測資料見 [§4](#lfhf)。

一句話版本：LF/HF 在我們的量測情境下**不收斂**——它在單次 5 分鐘的
錄製裡就從 −39% 漂到 +63%。給一個數字會比給 null 更糟，因為那個數字
看起來完全合理，而下游沒有任何方法判斷它不可信。

#### `ans`

**永遠回 `null`**，兩個獨立的理由：

1. 你的 `ans` 定義源自 LF/HF，而 LF/HF 我們不給
2. **就算給了也是另一個東西。** 我們有一個時域的替代值
   （`ansTimeDomain` = SNS − PNS，全部用時域指標合成，30 秒算得出來），
   但它跟 LF/HF 導出的 `ans` **定義不同、尺度不同**，兩台裝置的數字
   **不可互相比較，也不該存進同一個欄位**。

> 如果你希望我們填這個欄位，可以——但要先講定：填進去的會是時域替代值，
> 語意與攝影機端的 `ans` 不同。這需要你那邊確認下游（特別是 LLM prompt
> 與任何跨裝置的比較邏輯）能接受定義變更。**未經確認我們不會自己塞。**

<a id="lfhf"></a>
## 4. 為什麼 `lf_hf` 與 `ans` 回 null

### 4.1 LF 與 HF 分別在量什麼

HRV 頻譜分析是把 **RR 間期序列**的起伏拆解成不同週期的成分。

| 頻帶 | 範圍 | 週期 | 生理來源 |
|---|---|---|---|
| **HF** | 0.15~0.4 Hz | 2.5~6.7 秒 | 呼吸性竇性心律不整（RSA） |
| **LF** | 0.04~0.15 Hz | 6.7~25 秒 | 壓力反射振盪（Mayer wave） |

**HF 的機制很清楚。** 吸氣時腦幹抑制迷走神經輸出 → 心跳加速；吐氣時
解除 → 心跳減慢。正常呼吸 12~20 次/分 = 0.2~0.33 Hz，HF 頻帶的邊界
就是照人類呼吸速率畫的。

而且 **HF 只可能是副交感的**——這是機制上的必然，不是統計觀察：

| | 傳導物質 | 作用時間 |
|---|---|---|
| 迷走神經（副交感） | 乙醯膽鹼 | **一拍之內**（分解極快） |
| 交感神經 | 正腎上腺素 | **數秒**（清除慢） |

交感神經在生理上就是一個低通濾波器，物理上產生不出 0.15 Hz 以上的振盪。

**LF 就混濁得多。** 主峰 0.1 Hz 來自壓力反射的負回饋迴路（血壓上升 →
壓力感受器 → 腦幹 → 心跳變慢、血管舒張 → 血壓下降 → 反覆）。帶延遲的
負回饋必然振盪，延遲長度決定它落在 0.1 Hz。

但那個迴路**兩條神經都用**：對心臟走迷走（快），對血管走交感（慢）。
所以 LF 裡兩種成分混在一起。它還會被慢呼吸（6 次/分 = 0.1 Hz，直接
搬進 LF 帶）、姿勢、體溫調節污染。

`LF/HF` 這個比值最早（Pagani 1986）被解釋為「交感/副交感平衡」，
但那個前提已被大量證據推翻——例如阻斷迷走神經的阿托品會大幅消掉 LF，
若 LF 是純交感的就不該如此。

### 4.2 實測：同一段錄製切成不同窗長

我們寫了一個測試工具：錄製一段連續資料，然後把**同一段**切成不同長度
的滑動窗各自算 LF/HF。這樣唯一的變數就是窗長——受測者、心跳、生理狀態
全部相同。

（**不是量兩次比較**——兩次之間人的呼吸與狀態都變了，測到的差異會分不清
是窗長造成的還是生理變化造成的。）

#### 「偏差 %」到底是誰跟誰比

先把算法講清楚，後面的數字才讀得懂。

**基準 = 用完整錄製長度算出來的那一個 LF/HF。** 那次 5 分鐘錄製的
基準是 **0.91**（298 秒、344 拍）。

然後把**同一段資料**切成小塊，每塊各自再算一次 LF/HF，跟基準相減：

```
偏差% = (這個窗算出來的值 − 基準) ÷ 基準 × 100
```

實際代進去（2 分鐘窗那一組，基準 0.91）：

| 窗 | 這段算出來 | 計算 | 顯示 |
|---|---|---|---|
| 0–120s | 0.70 | (0.70 − 0.91) ÷ 0.91 | −23% |
| 30–150s | 0.55 | (0.55 − 0.91) ÷ 0.91 | **−39%** |
| 60–180s | 0.67 | (0.67 − 0.91) ÷ 0.91 | −26% |
| 90–210s | 0.59 | (0.59 − 0.91) ÷ 0.91 | −35% |
| 120–240s | 0.86 | (0.86 − 0.91) ÷ 0.91 | −5% |
| 150–270s | 1.15 | (1.15 − 0.91) ÷ 0.91 | +26% |
| 180–300s | 1.48 | (1.48 − 0.91) ÷ 0.91 | **+63%** |

所以「−39%」的意思是：**只看第 30~150 秒這兩分鐘，算出來的 LF/HF 是
0.55，比用完整 5 分鐘算出來的 0.91 低了 39%。**

**「偏差中位數」**則是把上面七個數字取絕對值（不管正負、只看差多少）
排序後取中間那個：

```
5, 23, 26, [26], 35, 39, 63   →  中位數 = 26%
```

用中位數而不是平均，是因為實測遇過手抖那次有單一窗偏差 818%，
平均會被它整個帶走，中位數不會。

#### 結果

**對 5 分鐘基準（Task Force 1996 的標準長度）：**

| 窗長 | 偏差中位數 | 落在 ±20% 內 |
|---|---|---|
| **30 秒**（我們產品的長度） | **42%** | 6 / 28 |
| **2 分鐘** | **26%** | 1 / 7 |

30 秒的結果在預期內。**2 分鐘那一列才是關鍵**：連 2 分鐘的窗都偏離
5 分鐘參考達 26%。所以問題不只是「30 秒太短」——**2 分鐘也不是穩定的
參考基準**。

> 換個方式想:如果量身高量五分鐘得到 170 公分,只取其中兩分鐘卻算出
> 130 公分、換另外兩分鐘算出 277 公分 —— 身高當然不會這樣,但 LF/HF
> 就是這樣。同一段資料、同一個人、同一個當下,只是換了觀察的時間區間,
> 答案就差這麼多。

### 4.3 它在漂移，不是在抖動

把 2 分鐘窗照時間排開：

```
0–120s    −23%        120–240s    −5%
30–150s   −39%        150–270s   +26%
60–180s   −26%        180–300s   +63%
90–210s   −35%
```

**單調往上爬**，從 −39% 一路到 +63%，在單一段 5 分鐘錄製之內。

這代表 LF/HF **不是繞著某個穩定值上下抖、而我們取樣太短**——
**它本身就一直在漂移**。任何窗長都逃不掉；窗只決定你在漂移曲線的
哪一段取樣。

我們也在半小時內對同一個人做了五次獨立的 2 分鐘錄製：

| # | 基準 LF/HF | 30 秒窗偏差中位數 | ±20% 內 |
|---|---|---|---|
| 1 | 0.60 | 48% | 3/10 |
| 2 | 0.84 | 58% | 2/10 |
| 3 | 0.20 | 50% | 2/10 |
| 4 | 0.21 | 58% | 2/10 |
| 5 | 0.60 | 64% | 2/10 |

**基準本身從 0.20 跳到 1.97**（含更早的兩次錄製），差了將近 10 倍。

### 4.4 結論

1. **30 秒不可用** — 對 5 分鐘標準偏 42%，只有 6/28 落在 ±20% 內
2. **2 分鐘也不是可靠基準** — 偏 26%，1/7 落在 ±20% 內
3. **拉長量測時間不會解決** — 訊號本身在漂移，不是取樣不足

所以這不是「我們的裝置做不到」，而是**這個量在這個情境下量不到穩定的
東西**。就算讓使用者坐 5 分鐘，拿到的也只是漂移曲線上的一個點。

> 附帶一提：Apple 健康 App 的 HRV 只提供 SDNN，同樣不提供 LF/HF。
> 這不構成證據，但可以視為獨立達成的相同判斷。

### 4.5 那該用什麼取代

**LF/HF 裡機制真正站得住的那一半是 HF（副交感）。**

而 **RMSSD 與 HF 的相關性通常 > 0.9** ——RMSSD 是一階差分，
在訊號處理上就是高通濾波器，本質上量的是同一件事。

| | 需要什麼 | 30 秒可用 |
|---|---|---|
| HF | 頻譜分析，至少 60 秒 | 邊緣 |
| **RMSSD** | 只要相鄰兩拍相減 | ✅ **文獻驗證過** |

**所以 `lf_hf` 想表達的、而且唯一可信的那一半，`rmssd` 已經在回應裡了，
而且是用 30 秒就穩定可靠的方式給的。**

給不了的是交感那一半——而那一半 LF 本來就沒有真的量到。

## 5. 額外提供的欄位

`/vitals` 回應裡還有一些你的介面沒列、但可能有用的東西：

| 欄位 | 說明 |
|---|---|
| `bpm` | 最近 6 拍中位 RR 換算的心率（反應快，適合即時顯示） |
| `spo2` | 血氧飽和度（%） |
| `fingerPresent` | 有沒有偵測到手指 |
| `settling` | 沉澱中——手指剛放上，數值還不能用 |
| `sqiOk` | 訊號品質閘門（布林；`sqi` 的來源） |
| `hrv.pnn50` | 相鄰間期差 > 50 ms 的比例（%），副交感指標 |
| `hrv.sd1` / `hrv.sd2` | Poincaré 短軸 / 長軸 |
| `hrv.hrvScore` | 0~100 的親切分數 = `ln(RMSSD) × 20`，clamp 到 0~100。**只適合跟自己比，沒有對常模校準** |
| `hrv.beats` | 這組統計用了幾拍（`confidence` 的主要依據） |
| `totalSamples` | 累積收到的樣本數（100 = 1 秒） |

### 建議額外導出

以下核心已經算好、只是還沒放進 HTTP 回應，如果對你有用告訴我：

- **`rrPoints`（RR 間期陣列）** ← **投報率最高**
  所有 HRV 指標都是從這一條序列導出的。有了它，你可以自己算任何需要的
  東西（pNN20、其他壓力指數、自訂分數），不用一個一個等我們加欄位。
- **`spikeMax`** — 連續的體動指標（可能對應你的 `activity`）
- **`cv`** — SQI 的另一個零件，若要連續版的 `sqi` 會需要它（需改核心）

<a id="usage"></a>
## 6. 建議的使用方式

### 讀值之前先檢查

```js
// 1. 手指在不在
if (!v.fingerPresent) return; // 沒有量測

// 2. 沉澱期的數值不可用
if (v.settling) return;       // 手指剛放上，等訊號穩

// 3. 可信度
if (v.confidence === null) return;          // 拍數不足
if (v.confidence === 'very rough') { /* 標記或重量 */ }
```

### 指標的優先順序

| 目的 | 用什麼 | 為什麼 |
|---|---|---|
| 放鬆 / 恢復程度 | **`rmssd`** 或 `ln_rmssd` | 機制清楚、30 秒驗證過、等同 HF |
| 心率 | `mean_hr` | 全窗平均，比 `bpm` 穩定 |
| 整體變異 | `sdnn` | ⚠️ 不同窗長之間不可比 |
| 這次量測可不可信 | `confidence` + `sqi` | 工程指標，不是生理量 |
| 偏交感 / 偏副交感 | `pns`（+ `stress` 當粗略參考） | 常模未校準，看方向不看絕對值 |
| 自律神經平衡 | — | **無法提供，見 §4** |

### 兩個容易誤用的地方

1. **不要跨裝置比較絕對值。** 我們的 `pns` 沒有用 Kubios 常模校準，
   `sdnn` 受窗長影響。同一台裝置前後比較是有意義的，跨裝置不是。
2. **不要把 `null` 當成 0。** `lf_hf` / `ans` 恆為 null 是刻意的設計。
   若 LLM prompt 對缺欄位的處理會退化，請明確處理 null，不要填預設值。
