# 可信度（`confidence`）

> 目前版本：server **0.0.0.7**（commit `86f0436`，2026-10-28）
> 實作：[k2_vitals_metrics.dart](../lib/main_mode/max30102_K2/k2_vitals_metrics.dart) 的 `confidenceByPulse` / `rrGaps()`

---

## 1. 現行規則

```
SQI 過關  且  拍數 ≥ 9  且  RR 沒有空洞   →  good
其他（含手指離開、沒資料）              →  very rough
```

- 只有兩級，**不會出現 `rough` 與 `null`**。
- 拍數 = RR 數 + 1（谷數）。9 = `Max30102HrvCalculator.minBeatsForHrv`，少於 9 拍核心不出 HRV。
- 判斷範圍：
  - server：整段保留中的 RR（手指放上去起算，最長 30 秒，手指離開就清空）
  - App 固定窗模式：畫面上那 12 秒

---

## 2. 為什麼這個欄位重要：站台拿它把關

站台（aquivio-station）在**呼叫推薦之前**先看 `confidence`：

```ts
// VitalsFlow.tsx / VitalsScan.tsx
const reliable = !!result
    && result.confidence !== null
    && result.confidence !== 'very rough';
if (!reliable) return;   // 不去要推薦
```

| `confidence` | 站台行為 |
|---|---|
| `good` | 顯示結果並請求推薦 |
| `rough` | 請求推薦，畫面多一行「近似讀數」黃字 |
| `very rough` / `null` | **不請求推薦** |

- 上表是**攝影機流程**（`VitalsFlow.tsx` / `VitalsScan.tsx`）。

### ⚠️ 手指流程**不看** `confidence`（2026-10-28 確認）

站台原始碼 `aquivio-station-main`（10/28 版）已併入手指流程（`useVitalsFingerScan.ts` / `VItalsFingerCore.tsx`），它的把關是**倒數計時**，不是可信度：

```ts
// useVitalsFingerScan.ts
const reliable = recommendVitalsSubmitRef.current !== null   // 收到過 strapi 區塊
    && secondsToScan === 0;                                   // 12 秒倒數結束
```

- `SECONDS_UNTIL_RELIABLE = 12`（`utils/finger_vitals.ts`）。第一次收到 `sqiOk = true` 開始倒數，**手指離開才重設**；倒數開始後 SQI 再變差也不會停。
- 倒數到 0 那一刻，把**最新一份** `strapi` 區塊送去要推薦。
- `confidence` 只出現在提示詞的 `Reading confidence: X`（fastify 與站台自己的 `recommender/recommendPrompts.ts` 都是），沒有規則用到它。

**所以在手指流程裡，`very rough` 不會擋下推薦**，只會讓模型看到那一行字。要「掉拍就不推薦」，得由站台在 `reliable` 加上 `confidence` 的判斷。

站台打包的 `scripts/max30102_server` 是 **0.0.0.6**（可信度仍是 SNR 版）。啟動方式：每個找到的手指感測器一支，`--mode serial --serial <裝置> --port 8770+n`，並帶 `LIBSERIALPORT_PATH`。

## 3. RR 空洞

### 定義

```
for i = 0 … n−2:
    if rrPoints[i+1].startAbs ≠ rrPoints[i].endAbs  →  空洞
```

- 核心收拍時，下一拍的起谷**直接拿上一拍的終谷**，所以連續的拍一定完全相等，不需要容差。
- 不設長度門檻，多大的空洞都算。
- **不必複製生理閘門的門檻**：不管是哪一道擋掉，結果都是留下空洞。以後調閘門不用回來改這裡。

### 一拍從被抓到、到進 HRV 要過的關卡

| 關卡 | 位置 | 條件 | 留下空洞？ |
|---|---|---|---|
| ① SQI | `k2_beatseries.feed()` | 這一輪 SQI 沒過 → 這輪的谷不記 | ✅ |
| ② 補漏拍 | 同上 | **預設關閉**(`searchBackEnabled = false`)。開啟時:間隔 > 最近 9 拍中位數 × 1.6 → 回頭找漏掉的谷 | 補成功 ❌ / 補不成功或沒開 → 往下 |
| ③ 生理閘門（過長） | 同上 | > `60000 / hrMin` = **2000 ms**（30 bpm） | ✅ |
| ③ 生理閘門（過短） | 同上 | < `60000 / hrMax` = **250 ms**（240 bpm） | ❌ 當成假谷，基準不推進，下一拍直接跨過它量 |
| ④ 誤拍過濾（長側） | 同上 | 與最近 9 拍中位數差 > 40% | ✅ |
| ④ 誤拍過濾（短側） | 同上 | 同上 | ❌ 同過短假谷 |
| ⑤ clean() | `k2_hrv_calculator` | 與整段中位數差 > max(2.5 × 1.4826 × MAD, 0.5 × 中位數) | ✅ |
| 訊號中斷 | `markDiscontinuity()` | 起點被清掉 | ✅ |

**空洞 = 有一拍掉了，而且沒補回來。**

### 補漏拍（search-back）

**預設是關的**（`Max30102Config.searchBackEnabled = false`，「寧缺勿假」）。App 可以在參數面板手動打開；server 用預設值，**沒有開**。所以到 2026-10-28 為止的快照，掉拍全部都是「沒去補」，不是「補不成功」。

> ⚠️ 更正：本文件第一版寫「10/8 14:26 已滿 9 拍、補漏拍有在運作，還是沒補成功」——錯的。當時沒查開關，補漏拍根本沒跑。

打開之後的限制：

- 要先累積滿 9 拍才會啟動。12 秒、心率 70 的人，前約 8 秒漏拍不會補。
- 回頭找到的谷，切出來每一段都要落在中位數的 0.6~1.5 倍，而且找到的谷數不能超過「應該漏掉的拍數」，否則整批放棄。
- 它也會補非手指的雜訊：照木頭那份打開補漏拍後，3 個空洞會被「補」掉 2 個（還剩 1 個，仍是 very rough）。

### 補漏拍讀錯通道（已修，2026-10-28）

補漏拍回頭讀波形用的 `_irAt()` 直接讀核心緩衝 `_ir`，而緩衝存的是**線上原始槽位**。LED 裝反的模組（8 片中 7 片）那一槽其實是紅光 —— 補漏拍一直在紅光上找谷。紅光脈動弱，放寬門檻後雜訊起伏也被當成谷，「只漏 1 拍卻找到 2 個谷」→ 整批放棄。

修法：`_irAt()` 與 `_compute()` 共用同一個方向判斷（`_assumedOrient`）。

**實測影響：看不出來。** 打開補漏拍、拿快照實際採用的谷重跑 `BeatSeries`，只換讀的通道，
裝反模組的 8 份快照**讀紅光與讀真 IR 結果完全相同**（紅光的脈搏時間點與 IR 一致，
對補漏拍夠用）。修正在程式上是對的，但不是掉拍補不回的原因。

> ⚠️ 更正：第一版這裡有一張「讀紅光補不回、讀真 IR 補回」的對照表 —— 錯的。
> 當時把快照波形對到谷的位置算錯一拍（見 §5 的換算說明），比較的是錯的區段。

打開補漏拍後（兩個通道相同）：

| 快照 | 掉拍 | 結果 |
|---|---|---|
| 10/28 15:37、15:41 | 1360 ms | **補回**，空洞歸零 → good |
| 10/8 14:26、10/13 11:15 | 1640、1670 ms | 補回（10/13 另有 5520 ms 晃動） |
| 10/8 14:41 | 1380、1540 ms | 補回 1540，1380 補不回 |
| 10/28 13:58 | 1290、3430 ms | 都補不回 |
| 10/28 16:30 | 880、2030 ms | 都補不回（880 未達 1.6 倍不觸發；2030 切不出合理的拍） |

補漏拍沒開時（預設），這個修正**不影響任何輸出**。

### 看不到的地方

只看得到夾在兩個被接受的拍之間的中斷。第一拍之前、最後一拍之後的中斷看不到。

## 4. 為什麼不用其他做法

### 不用攝影機的 SNR（0.0.0.3 ~ 0.0.0.6 的做法）

- 照抄 aquivio-vitals 的 `hrv_confidence()`：f0 與 2f0 各 ±0.2 Hz 的能量算訊號，0.5~4 Hz 其餘算雜訊；≥ 6 dB good、≥ 1 dB rough。
- 攝影機訊號弱（像素變化 0.1~0.5%），需要先確認有沒有脈搏；手指訊號強一到兩個數量級。
- 對手指而言 SNR 混了三件事：心率穩不穩（HRV 越好越吃虧）、波形銳利度（3 次以上諧波算雜訊）、動作干擾。
- 攝影機原始碼現在找不到（本機與網路上都沒有），定義以當時抄進註解的為準。
- **仍然有送**：`confidence_video` 維持這套三級，`snr_db` 照送原始數值。

### 不只看 SQI（`f3ac733`，0.0.0.7 第一次 push，未交付）

SQI 的門檻很寬（cv < 0.35），有手指時幾乎都是 1。實測擋不住：

| 快照 | 情況 | 只看 SQI |
|---|---|---|
| 10/28 13:36 | 照木頭：心率 150、RMSSD 146、血氧 99.9 | good ❌ |
| 10/28 13:58 | 晃動中斷 3430 ms + 漏拍 1290 ms | good ❌ |

### 不只看「≥ 9 拍」

數的是**通過**考驗的拍，不是「有沒有拍沒通過」。

| 快照 | 進 HRV 的拍數 | 只看 ≥ 9 拍 |
|---|---|---|
| 木頭 | 24 | good ❌ |
| 晃動 3.4 秒 | 9 | good ❌（剛好 9） |
| 10/8 14:26 漏一拍 | 15 | good ❌ |

### 不靠核心丟掉的篩除紀錄

`feed()` 會回傳剔除紀錄（位置 + 原因），但 `k2_core` 收到後直接丟掉（`k2_core.dart` 呼叫 `_beats.feed()` 那行）。要用它得改 `k2_beatseries` 與 `k2_core`；空洞從 RR 列表就看得出來，只需改 `k2_vitals_metrics`。

### 快照波形與谷位置的換算

定長模式的快照裡，`ir` / `red` 從 `base` 起算，`goldTroughs` 存的是**每拍的終谷**：

```
base       = rrEndAbs[0] − goldTroughs[0]
波形索引    = 絕對位置 − base
```

> ⚠️ 不要用 `rrStartAbs[0] − goldTroughs[0]`，那會錯一拍（約 0.7 秒）。第一版的
> 「空洞裡有沒有谷」分析就是這樣算錯的，已刪除。用正確換算時，谷落在去趨勢後
> IR 的局部最低點上（10/28 15:37：14 / 14；錯誤換算只有 6 / 14）。

### 例：10/28 16:30 的 2030 ms 空洞

```
RR: … 670 650 670 680 │ 390 │ [空洞 2030] │ 540 780 │ 700 740 710 690
```

空洞裡 +370 ~ +590 ms 有一個**很深、很寬、雙底**的谷（一般谷深的 2.8 倍、約 400 ms 寬），
IR 與紅光同步同比例下降 → 真實的光學變化。可能是手指壓力突變（這份開頭 RR 也很亂），
也可能是早搏（先一個 390 ms 短拍，之後停頓、再一個特別大的脈搏）。分不出來，但這段 HRV
不能信，very rough 是對的。

### 代價

正常手指漏了一拍、補漏拍又沒補回來的，也會變成 very rough，站台就不去要推薦。估計**約每 5 次 1 次**（10/8 那批 18 份中 4 份、10/15~16 共 6 份中 1 份）。

## 6. 送出的相關欄位

| 欄位 | 內容 | 0.0.0.6 | 0.0.0.7 |
|---|---|---|---|
| `confidence` | 站台把關用 | SNR 三級 / `null` | **SQI + 拍數 + 空洞，兩級** |
| `confidence_video` | 攝影機的判法 | 與 `confidence` 同值 | 維持 SNR 三級，**不再同值** |
| `snr_db` | 原始 dB | 照送 | 照送 |
| `sqi` | SQI 閘門 1 / 0 | 照送 | 照送 |
| `confidence_by_beats` | 拍數版（20 / 13 拍，為 28 秒視窗訂的） | 照送 | 照送 |

`confidence` 現在**永遠不是 `null`**：以前沒資料時送 `null`，現在送 `very rough`。站台對兩者處理相同（都不推薦），但若對方的手指流程用「`confidence` 有沒有值」判斷「有沒有結果」，行為會不同。

## 7. 尚未採用的候選條件（之後再判斷）

### 波動幅度 AC/DC（IR 起伏 ÷ 平均亮度）

| 對象 | AC/DC |
|---|---|
| 手指（24 份） | 0.82% ~ 5.4%（晃動那份 13%） |
| 木頭 | 0.20% |
| 10/12 兩份 | 0.12%、0.20% |

兩群差 4 倍以上、沒有重疊。除以 DC 會消掉模組亮度差異（與通道方向判定同一個道理）。候選門檻約 **< 0.5%**。

### IR 與 RED 的相關係數

真脈搏是血液在動，兩顆 LED 照同一團血，IR 與 RED 一定同起同落。

| 對象 | IR-RED 相關 |
|---|---|
| 手指（25 份，含晃動） | **+0.98 ~ +1.00** |
| 木頭 | +0.06 |
| 10/12 兩份 | +0.46、+0.82 |

可當第二道保險；10/12 那份 +0.82 偏高，單用不夠可靠。候選門檻約 **< 0.9**。

### 血氧 < 80% 視為雜訊

木頭算出 99.9%，所以這條抓不到木頭，抓的是另一種雜訊。核心另有 `spo2Valid`（70~100）沒套用。

### 不建議：調高生理閘門下限

把 250 ms 拉到 400 ms（150 bpm）只能擋掉木頭約一半的假拍；而 `hrMax` 同時決定濾波頻帶與找谷最小間距，會連帶改變正常量測結果。

**換算**：250 ms = 240 bpm、400 ms = 150 bpm、2000 ms = 30 bpm（心率 bpm = 60000 ÷ RR ms）。

> 以上門檻只用 29 份快照訂，木頭只有 1 份。正式採用前要多量幾種非手指（桌面、紙、手掌側邊、手指沒壓好）。
