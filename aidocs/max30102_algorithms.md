# MAX30102 心率 / 血氧 運算方式總覽

> 本文件對照實作：[`lib/main_mode/services/max30102_algorithm.dart`](../lib/main_mode/services/max30102_algorithm.dart)
> （顯示/平滑/趨勢另見 [`max30102_controller.dart`](../lib/main_mode/controllers/max30102_controller.dart)、[`max30102_page.dart`](../lib/main_mode/widgets/max30102_page.dart)）

---

## 名詞

- **FS**：Sampling Frequency = **取樣率**，每秒採幾筆。本專案 **FS = 100 Hz**（每筆 0.01 秒，STM32 韌體設定）。
  心率公式 `HR = 60 × FS / 間距(樣本數) = 6000 / 間距`，把「間距樣本數」換算成 bpm。
- **DC**：訊號的直流成分（背景光位準）≈ 視窗平均。
- **AC**：訊號的交流成分（脈搏起伏振幅），AC 只佔 DC 約 0.5~2%。
- **R**：血氧比值 `R = (AC_red/DC_red) / (AC_ir/DC_ir)`，SpO2 經驗公式的輸入。

---

## 0. 架構與資料來源

- **STM32 = 搬運工**：MAX30102 晶片只吐原始 18-bit RED/IR FIFO（100Hz、小端序），
  STM32 透過 UART `0x09` 命令把原始值搬給上位機。**HR / SpO2 全部由上位機（本 Flutter app）自己算**。
- 一筆 = `(red, ir)`，存進雙環形緩衝（各 2000 筆 = 20 秒）。演算法每 `algoUpdateMs`（預設 1 秒）
  取最近 `algoWindowSamples`（預設 300 筆 = 3 秒）跑一次。
- **出處**：此「驅動只搬資料、計算自理」的分工與 libdriver/max30102 函式庫一致；協定見 in-repo `MAX30102_CHEATSHEET.md §7.4`。

### 前處理（三種訊號）
| 訊號 | 來源 | 用途 | 函式 |
|------|------|------|------|
| **原始 (raw)** | FIFO 直接值 | 舊版 HR / 舊版 SpO2 | — |
| **截尾 (trimmed)** | 原始經「截尾滑動平均」去突波 | 新版 HR / 新版 SpO2 | `_slidingTrimmedMean` |
| **去趨勢 (detrended)** | 減去長視窗移動平均（高通）+ 輕度平滑（低通） | 找峰 / 找谷的輸入 | `_movingAverage` |

- **截尾滑動平均**：每點取以自身為中心的視窗，**丟掉 1 個最大 + 1 個最小再平均** → 殺尖刺型突波。
  出處：自訂（despike，概念同 trimmed mean / 截尾平均）。
- **DC = 視窗平均**（`_meanD`）；**AC = 去 DC 後的 RMS**（`_rmsAc`）。

## 1. 心率 HR — 兩種運算

### HR-A 舊版：波峰平均間距法
- **輸入**：原始 IR（另對截尾 IR 也算一份 `hrTrim` 當對照，演算法同）。
- **步驟**（`_computeHr`）：
  1. 高通：`IR − movingAverage(IR, fs/bandLow)` 去掉呼吸漂移
  2. 低通：再 `movingAverage(_, fs/(2·bandHigh))` 平滑
  3. 找峰：`_findPeaks`（高於 `posMax×0.4` 門檻、最小間距 = `60·fs/hrMax` 的局部極大）
  4. **HR = 60 × FS / 平均峰間距**
- **特性**：簡單、即時，但吃原始值 → **尖刺突波易被誤判成峰 → HR 偏高**。
- **出處**：通用 PPG 教學作法（與 CAVEDU GitBook「偵測 IR 峰值、量兩峰時間差」同類）。

#### 「間距（樣本數）」怎麼來的
心率公式裡的「間距」= **兩個相鄰峰（或谷）在陣列裡的索引相減**，而索引本身就是「第幾筆樣本」。

**① 索引 = 第幾筆樣本**
演算法視窗是依時間排好的陣列 `[s0, s1, s2, … sN-1]`，每個元素是一筆 100Hz 取樣值。
索引 `i` = 視窗裡第 i 筆；因為固定 100Hz，**相鄰索引剛好差 0.01 秒**（索引 0→1 = 過 1 筆 = 10ms）。

**② 找峰/找谷回傳「索引清單」**
`_findPeaks` / `_findPeaksProminent` 掃過陣列，回傳峰/谷所在的**索引**。
例如找到波谷在 `troughs = [12, 91, 170, 249]`（代表第 12、91、170、249 筆是谷底）。

**③ 間距 = 索引相減**
```dart
for (int i = 1; i < troughs.length; i++) {
  intervals.add((troughs[i] - troughs[i - 1]).toDouble()); // 後一個索引 − 前一個
}
// 舊版 _computeHr 同理：sumInterval += (peaks[i] - peaks[i - 1]);
```
以上例：`91−12 = 79`、`170−91 = 79`、`249−170 = 79` → **間距 = 79 樣本**。

**④ 換算回時間 / 心率**
- 時間：`79 樣本 × (1/100Hz) = 0.79 秒 = 790ms` ← 波形上看到的「790ms」時間軸標註
- 心率：`HR = 60 × FS / 間距 = 6000 / 79 ≈ 76 bpm`

> 一句話：樣本以固定 100Hz 排成陣列 → 找峰/找谷得到它們的**索引**（第幾筆）→ 兩索引相減 = 間隔幾筆 = **間距(樣本數)** → ×10ms 得時間、套 `6000/間距` 得心率。
> 間距不是另外量的，而是「峰在陣列的位置」直接相減；前提是取樣率固定（每筆等距 10ms）。

### HR-B 新版（Maxim 風格）：波谷中位數 + 離群剔除
- **輸入**：截尾 IR（去突波）。
- **步驟**（`_computeMaxim` 第 1~3 段）：
  1. 去趨勢 + 平滑後，對 **−訊號找峰 = 找谷**（谷 = 供血，反射式 PPG 的脈動下陷）
  2. 找谷用 **prominence（顯著度）門檻**：門檻 = `promRatio × p70(各候選 prominence)`，
     而非絕對深度 → 抗呼吸造成的重複抓（double-count）。（`_findPeaksProminent`）
  3. 谷間距 → **生理閘門**（bpm 落在 hrMin~hrMax）+ **與中位數比剔除離群**
     （> 1.5× 或 < 0.5× 中位數 → 視為漏拍/多抓，剔除）
  4. **HR = 60 × FS / 谷間距中位數**
- **與 HR-A 的關係**：「索引相減 → 間距 → 換算」的框架**完全相同**（見上方 HR-A 的「間距怎麼來」，HR-B 同理）。
  差別只在 ④ 點：**輸入**（原始→截尾）、**抓的點**（峰→谷）、**找點門檻**（絕對→prominence）、**統計**（平均→中位數+離群剔除）。
- **特性**：抗突波、抗漏拍/多抓，比舊版穩。
- **出處**：
  - 「找谷 + 逐拍」精神 ← Maxim 官方 `algorithm.cpp`
  - prominence 找峰 ← `scipy.signal.find_peaks(prominence=…)` 概念，Dart 自寫
  - 中位數 + 離群剔除 ← 自訂強化

## 2. 血氧 SpO2 — 三種運算

共同基底：**R 比值 → 經驗公式**。R 的標準定義
`R = (AC_red / DC_red) / (AC_ir / DC_ir)`。

> ⚠️ **三種不是三套獨立管線**，而是 **2 個 R × 2 條公式** 組出 3 種顯示：

| 顯示 | R 來源（AC/DC 取法） | 公式 |
|------|------|------|
| **舊** | 整窗 RMS（`ratio`） | 二次多項式 |
| **新·線性** | 逐拍 B 點中位數（`ratioNew`） | 線性 110−25R |
| **新·逐拍** | 逐拍 B 點中位數（`ratioNew`） | 二次多項式 |

- **新·線性 與 新·逐拍 用同一個 R**（`ratioNew`），只差最後公式 → 趨勢圖 R 線重合、只有 SpO2 線分開。
- 只有「舊」是另一個 R（整窗 RMS）。
- 設計目的＝**一次只變一個變數**：**舊↔新逐拍**（同二次公式）看 R 取法差異；**新線性↔新逐拍**（同逐拍 R）看公式差異。

兩條經驗公式（`spo2FromR`）：
| 公式 | 式子 | 出處 |
|------|------|------|
| **二次多項式** | `SpO2 = −45.06·R² + 30.354·R + 94.845` | Maxim / SparkFun 應用註記擬合 |
| **線性** | `SpO2 = 110 − 25·R` | CAVEDU GitBook（簡化經驗式） |

### SpO2-1 「舊」：整窗 RMS + 二次多項式
- **R 來源**：整個視窗的 `AC=RMS / DC=平均`，**整窗算一個 R**（`ratio`）。
- **公式**：二次多項式。
- **特性**：等同 CAVEDU 教學版；整窗 RMS **會把基線漂移/突波算進 AC → R 被撐大、易亂跳**。
- **出處**：CAVEDU GitBook（整批 RMS-AC / 平均-DC）+ Maxim 二次公式。
  程式位置：`compute()` 第 3 段。

### SpO2-2 「新·線性」：逐拍 B 點 + 中位數 R + 線性公式
- **R 來源**：逐拍 B 點（見下）取得每拍 R，**取中位數**（`ratioNew`）。
- **公式**：線性 `110 − 25·R`。
- **特性**：R 較乾淨，但**線性公式在低 R 區會給出 >100% 的不合理值**（對照用，凸顯公式差異）。
- **出處**：逐拍 ← Maxim；線性公式 ← CAVEDU。

### SpO2-3 「新·逐拍」：逐拍 B 點 + 中位數 R + 二次多項式
- **R 來源**：同 SpO2-2 的逐拍中位數 R（`ratioNew`）。
- **公式**：二次多項式。
- **特性**：目前**最可信**的一版（逐拍去漂移 + 截尾去突波 + 合理公式）。
- **出處**：逐拍 B 點 + 中位數 ← Maxim `algorithm.cpp` 精神（中位數為自訂強化）。

> **逐拍 B 點法**（`_acDcBeat`）：在相鄰兩谷 `[a,b]` 之間，
> 峰值 `pv` 為 DC；基線 B 點 = 兩谷對峰值位置的**線性內插** `x[a]+(x[b]−x[a])·(pk−a)/(b−a)`；
> **AC = pv − B 點**。這樣會自動扣掉「這一拍內的基線斜率（呼吸/漂移）」。

### 三種能對照出什麼
- **SpO2-1 ↔ SpO2-3**（都用二次公式）→ 差異 = **AC/DC 取法**（整窗 RMS vs 逐拍 B 點）。
- **SpO2-2 ↔ SpO2-3**（都用逐拍 R）→ 差異 = **公式**（線性 vs 二次）。
  注意：SpO2-2、SpO2-3 用的是**同一個 R**，趨勢圖 R 線會重合，只有 SpO2 線因公式分開。

## 3. 訊號品質 SQI（只作燈號，不擋顯示）

新版三關（`_computeMaxim` 第 5 段）全過才算可信：
1. `cv`（谷間距變異係數） < 0.35
2. `spike`（振幅突波比 = 最大振幅 / p70） < 5.0
3. 有效拍數 ≥ 2

- **目前策略（選項 A）**：SpO2 三種值**永遠顯示最新**、不因 SQI 凍結；
  SQI 只在 UI 以**燈號**呈現（🟢 綠=可信 / 🟡 黃=訊號差），舊版無 SQI 概念故無燈號。
- 強基線漂移時 `spike` 容易超標 → 常亮黃燈（值仍照給）。
- **出處**：自訂。

## 4. 輸出平滑 EMA

- 顯示值（三種 SpO2）皆套 **指數平滑** `EMA = F×舊 + (1−F)×新`（`spo2SmoothFactor`，預設 0.7）。
- `F=0` 等同不平滑；`F=0.7` ≈ CAVEDU 的輸出平滑（穩但慢半拍）。
- **出處**：仿 CAVEDU GitBook 的 `ESpO2 = 0.7·舊 + 0.3·新`。
- 位置：`_runAlgorithm()`。

## 5. 主要可調參數（`Max30102Config`）

| 參數 | 預設 | 影響 |
|------|:----:|------|
| `fingerThreshold` | 50000 | 手指偵測（IR DC 門檻） |
| `bandLowHz` / `bandHighHz` | 0.5 / 4.0 | 帶通濾波（對應 30~240 bpm） |
| `algoWindowSamples` | 300 (3s) | 每次計算吃多長資料（影響 R 穩定度） |
| `algoUpdateMs` | 1000 | 多久重算一次（決定趨勢點密度） |
| `hrMin` / `hrMax` | 30 / 240 | HR 生理閘門 |
| `spo2Min` / `spo2Max` | 70 / 100 | SpO2 合理範圍 |
| `trimWindow` | 9 | 截尾滑動平均視窗（去突波強度） |
| `promRatio` | 0.5 | 新版找谷的 prominence 門檻倍率 |
| `spo2SmoothFactor` | 0.7 | 輸出 EMA 平滑（0=不平滑） |
| `ledCurrentRed/Ir` | 0x24 (~7.2mA) | LED 電流（晶片端，影響 DC/AC/飽和） |

## 7. 未來可能強化（提醒，尚未實作）

> 來源：管線審查（資料接收→BPM→HRV）。此處只記「現在不做、但未來可能用到」的點，避免遺忘。

### 7.1 訊號品質 / artifact rejection（治本，優先級高於任何濾波微調）
- **飽和偵測**：連續 N 點 IR/RED 逼近 18-bit 滿格（~262143）→ 光二極體飽和，谷為假。→ 可做。
- **手指離開 / 太暗**：局部 IR < `fingerThreshold`(50000) 或逼近 0 → 無脈動。→ 可做（與飽和合併判定）。
- **不合理暴衝**：相鄰點跳動超過生理可能 → 體動。→ 不細分，與上面合併為單一提示「請將手指穩穩放好」即可，避免大量設計參數。
- **平線 / 卡死偵測**（一小段 max−min ≈ 0 → ADC 卡住/接觸不良）：**目前不實作**（本測試介面用不到）；列此提醒，未來量產若遇接觸不良再評估。
  - 共通設計點（若日後實作）：壞段需有「最小長度」避免單點誤判；跨壞段的 RR 直接當 gap，不要硬補（避免造假 HRV）。

### 7.2 其他審查建議（細節見管線審查報告）
- HR 凍結加「逾時降級」（連續凍結 >6~8 秒顯示「請重新放穩手指」，避免把舊值/上一個人的值當當前值）。
- SQI `spike` 由「整窗單一最大」改「高百分位（取自 posOfNeg）」，門檻一併重新定標，減少單點造成的反覆凍結。
- HRV：RMSSD/SD1 只在「真正相鄰的 NN」間算差（加連續性旗標）；`_cleanRr` 改穩健離群（中位數 ± k·MAD）避免壓窄 SDNN；SDNN 改樣本標準差 (N−1) 與 RMSSD 一致。
- `algoWindowSamples` 預設應為 **500（5 秒）**，與本文件/CLAUDE.md 一致（程式預設目前為 300，待對齊）。
