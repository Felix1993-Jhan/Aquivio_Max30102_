## 4. 血氧

### 4.1 三種算法的對照設計（為什麼曾經有三個數字）

三種**不是三套獨立管線**，而是 **2 個 R × 2 條公式** 組出 3 種顯示：

| | 整窗 RMS 的 R | 逐拍 B 點的 R |
|---|---|---|
| 二次多項式 | SpO2-1 | **SpO2-3（現行）** |
| 線性 `110 − 25R` | （沒做） | SpO2-2 |

設計目的是**一次只變一個變數**：SpO2-1 ↔ SpO2-3（同二次公式）看 R 取法的差異；SpO2-2 ↔ SpO2-3（同逐拍 R）看公式的差異。驗證完之後只留現行那一個。

### 4.2 SpO2-1：整窗 RMS + 二次式　`已退場`

```
DC = mean(整窗)
AC = sqrt( Σ(v − DC)² / n )          // 整窗 rms
R  = (AC_red/DC_red) ÷ (AC_ir/DC_ir)  // 整窗只有一個 R
SpO2 = −45.06R² + 30.354R + 94.845
```

- **為什麼退場**：整窗 RMS **會把基線漂移與突波一起算進 AC** → R 被撐大、數字亂跳。逐拍 B 點法（主文件 §4.1）在每一拍之內扣掉基線斜率，這件事整窗版做不到
- **程式碼還在嗎**：`meanD` / `rmsAc` 還在 `k2_signal.dart`，但**不再組成 R** —— 它們現在只當 `irDc` / `irAc` / `redDc` / `redAc` 輸出給軟體端看訊號強弱、調 `fingerThreshold`
- **出處**：CAVEDU GitBook（整批 RMS-AC / 平均-DC）+ Maxim 二次公式

### 4.3 SpO2-2：線性公式　`已退場`

```
SpO2 = 110 − 25 × R
```

- **為什麼退場**：**低 R 區會給出 > 100% 的不合理值**。當初留著是為了凸顯「公式差異」這個變數
- **程式碼還在嗎**：**在，但永不觸發**。`Max30102Signal.spo2FromR(r, linear)` 的 `linear = true` 分支還在，可是呼叫端傳的是 `Max30102Config.spo2Linear`，而那是 `static const bool spo2Linear = false`（編譯期常數，UI 也沒有開關）
- **出處**：CAVEDU GitBook

## 6. 心率

三代的框架其實一樣：「索引相減 → 間距 → 換算」。差別在輸入、抓的點、找點門檻、統計方式。

| 代 | 做法 | 狀態 |
|---|---|---|
| HR-A | 原始 IR → 帶通 → `findPeaks` → **平均**峰間距 | `已退場`（整檔刪除） |
| HR-B | 截尾 IR → 去趨勢 → prominence 找**谷** → 生理閘門 + 離群剔除 → **中位數**間距 | `降級為閘門` |
| 現行 | 谷 → 絕對位置 → NN 序列 → `60000 / median(最近 6 筆)` | `現行`（主文件 §6.5） |

### 6.1 HR-A：波峰平均間距法　`已退場`

```
高通 = IR − MA(IR, fs/bandLowHz)
低通 = MA(高通, fs/(2·bandHighHz))
findPeaks：s[i] >= threshold 且 s[i] >= s[i−1] 且 s[i] > s[i+1]
           threshold = posMax × 0.4，相鄰 < minDist 時保留較高者
HR = 60 × fs / 平均峰間距
```

- **為什麼退場**：**吃原始值 → 尖刺突波易被誤判成峰 → HR 偏高**。而且用平均而非中位數，一顆假峰就把整段拉走
- **程式碼還在嗎**：`k2_legacy_algorithm` **整檔刪除**。`Max30102Signal.findPeaks` 還在共用層，但**全 repo 沒有任何呼叫者**（遺留孤兒）
- **同時刪掉的**：`HrSpo2Result` 的 20 個舊欄位（舊版 HR/SpO2 原始+截尾各一份、截尾 DC/AC、峰數、rank4a 的 P98 對照觀測）。結果：欄位 30 → 10，每輪省掉兩次完整帶通濾波 + 找峰
- **出處**：通用 PPG 教學作法（與 CAVEDU GitBook「偵測 IR 峰值、量兩峰時間差」同類）

### 6.2 HR-B：窗層谷中位數　`降級為閘門`

```
kept = 通過生理閘門與 [0.5,1.5]×medInt 的谷間距
HR   = 60 × fs / median(kept)
```

- **為什麼降級**：顯示用的心率改由 NN 序列（BeatSeries）取 —— 那條序列同時供 HR 與 HRV，**單一真相，不再各算各的**。窗層的 `median(kept) → hr` 是重複計算，而且它看不到跨輪累積的拍
- **程式碼還在嗎**：**在，但只剩 `beatsOk`**（中位間距是否落在生理範圍），當 SpO2 的閘門與空結果判斷用。見主文件 §3.2
- **出處**：「找谷 + 逐拍」精神來自 Maxim `algorithm.cpp`；中位數 + 離群剔除是自訂強化

## 7. HRV 時域

### 7.1 clean：固定 ±30% → MAD　`已更換`

```
舊：保留 |rr − median(全體)| <= 0.30 × median
新：保留 |rr − med| <= max( 2.5 × 1.4826 × MAD , 0.5 × med )
```

- **為什麼換**：固定百分比對每個人都用同一個寬度。MAD 版讓門檻**隨資料自身的離散度縮放** —— 高 HRV 的人不會被誤剔
- **殘留**：`k2_hrv_calculator.dart` 檔頭的 docstring 還寫著「全體中位數 ±30% 再濾一次」，那是舊描述

### 7.2 `minRelThresh` 舊值 0.15　`已更換為 0.5`

- **為什麼 0.15 不能用**：安靜時 MAD 只有 40 ms，`2.5 × 1.4826 × MAD ≈ 148 ms` → 帶寬只有 ±148，會把「真谷、真間距、只是中等偏離」的正常拍（例如 630~1030，離中位 150~210 ms）當離群砍掉。實測體動／訊號衰退期的真拍被誤剔
- **為什麼 0.5 安全**：真漏拍是 820 → 1640（離 820 有 820 ms），仍遠超 ±410，照擋
- **下限那一項不可省**：RR 有 10 ms 量化，安靜時 MAD 只有 1~2 格，純 MAD 門檻會塌到 ±25 ms，把正常的心率漂移（收 30 秒時 RR 從 780 爬到 900）整段砍掉

### 7.3 誤拍過濾 30% → 40%（2026-07）　`已放寬`

以「近 9 拍當前節律」為主要基準，只擋明顯離群，中等真變異留下。漏拍改由 search-back 回補，clean 的全域離群降級為對照開關。

### 7.4 `hrvScoreMax` 100 → 150　`已放寬`

- **為什麼**：原本 100 是分數的慣例，但實測會撞到 —— RMSSD 到 148 ms 就滿分，而深慢呼吸下的高變異真的量得到 130~230 ms，那時分數卡在 100，**分不出「很好」與「極高」**
- 放寬到 150 後對應 RMSSD 約 1808 ms，實務上等於不再設限。下限的 0 保留（RMSSD < 1 ms 時 ln 會變負，那是壞資料）
- **⚠️ 副作用**：超過 100 時不再是「滿分 100」的語意，呈現層的進度條要自己處理溢出

### 7.5 `ectopicK` 3.5 → 4.0　`已收緊`

少放輕度邊界，偏保守／通用。

### 7.6 可信度守門（圓團 SD1≥SD2 / 逐拍亂跳）　`已退場`

整段移除，理由一句話：**HRV 的數字與形狀不反映品質，品質看波形乾不乾淨。**

- **程式碼還在嗎**：`bigJumpRel = 0.25` 這個常數還在，但**只剩繪圖用途** —— Poincaré 圖上把「大跳」的散點標紅，不再拿來判可信與否

## 8. HRV 頻域

### 8.1 HF 門檻曾訂在 25 秒　`已退場`

早期版本把 HF 的可用門檻訂成「25 秒」，那是**為了讓我們自己的 30 秒視窗通過而調的**。

方向完全相反 —— **等於先射箭再畫靶**。現在改成單一規則：每個頻帶各自從自己的下緣頻率導出（4 個週期），沒有可以手動調的空間。結果 HF 需要 26.7 秒、LF 需要 100 秒。見主文件 §8.6。

### 8.2 `lf_hf` 曾經恆送 null　`已改為照送`

- **舊規則**：30 秒測不到 LF 就送 `null`
- **為什麼改**：後來確認**攝影機端（aquivio-vitals）同樣是 30 秒視窗**（他們的 `docs/VITALS.md`：*"The window is 30s (not 60s) across the station and the SDK"*），而且他們照樣把 `lf_hf` 算出來送
- 我們送 null 而他們送數字，只會讓同一個欄位在兩台裝置上行為不一致，下游反而更難處理 —— **分不出「沒有這個能力」和「刻意保留」**
- **現在的做法**：照送，但可信度資訊一起送（`lf_reliable` / `lf_cycles`）。**誠實靠標註，不靠藏數字**

## 9. 衍生分數

### 9.1 `confidence` 舊門檻 good ≥ 25 / rough ≥ 15　`已降為 20 / 13`

- **為什麼舊值不能用**：**門檻必須在自己的視窗上限內可達**。我們的視窗最長 30 秒（實際跨度約 28 秒），可達拍數是 `28 × bpm / 60`，所以 25 拍需要**心率 ≥ 54 bpm** —— 低於這個數的人（運動員、深慢呼吸時）**永遠拿不到 good**。實測就出現過 54 bpm 的讀數，正好卡在線上
- **現值**：`good ≥ 20 拍`（心率 ≥ 43 bpm）、`rough ≥ 13 拍`（心率 ≥ 28 bpm）
- 20 拍仍落在超短時 HRV 的文獻驗證範圍內（RMSSD 在 10~30 秒都驗過），**不是放寬標準，是修正一個訂了卻達不到的數字**

### 9.2 SNR 舊頻帶 ±0.1 Hz / 0.5~5.0 Hz　`已改為 ±0.2 / 0.5~4.0`

先前只搬了門檻常數（6.0 / 1.0 dB）卻沿用自己的頻帶定義，結果是「**拿他們的尺、用自己的刻度**」。

實測 8 份真機快照，我們一律偏低 0.35 ~ 5.10 dB，其中兩份因此被降級（good → rough）：

```
快照            心率   舊定義            他們的定義
08-26 10:39     69    4.46 dB rough     8.49 dB good
08-13 11:52     71    3.73 dB rough     7.79 dB good
08-17 11:10     87    7.19 dB good     12.28 dB good   (差 5.10)
```

**心率越高差越大** —— f0 越高，脈搏能量在頻譜上散得越開，窄窗漏掉的越多。兩處差異都往同一個方向壓：訊號窗窄一半（分子小）+ 多算 1 Hz 雜訊（分母大）。

現值對應 aquivio-vitals `core.py`：`SNR_BAND_LO_HZ, SNR_BAND_HI_HZ = 0.5, 4.0`、`SNR_PEAK_HALFWIDTH_HZ = 0.2`。

- **殘留**：`snrDb` 的 docstring 還寫著舊值（±0.1 / 0.5~5 Hz），與實作不符

### 9.3 `pns` 這個名字曾經指 z-score 版　`已改名`

現在：

```
pns    = 0~100 分版（RMSSD 的對數縮放，整合方尺度）
pns_z  = z-score 版（三項 z 平均，我們自己的尺度）
```

`docs/VITALS_FIELDS.zh-TW.md` 的第 9 節講的還是舊的（z-score 版佔用 `pns` 這個名字）。

### 9.4 `activity` 曾經不提供　`已提供`

舊文件寫「⬜ 不提供 —— 需要你提供」，現在有 `activityScore`（主文件 §9.5）。
